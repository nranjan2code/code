What happens here

Tools execute across a broker boundary into a disposable process group. Built-in tools use the versioned __tool_worker protocol; MCP tools run as separately sandboxed workers. The permission engine evaluates precedence: explicit deny rules, then ask rules, then allow rules, and only then the mode's own default.

Non-negotiable Invariant 14: Model tools cross a broker boundary. Never give a worker the policy engine, credentials, or control-plane handles.

What each surface is

Pick by where you are and what you need to see, not by what it can do — the policy and the record do not vary.

CLI vak exec, vak plan, goal mode with acceptance criteria, vak intent explain, vak commit list, vak config dump, vak doctor. The headless surface, and the one CI uses.
Desktop app Tauri 2. Isolated worktrees, streaming chat, diff review, an editor, a PTY terminal, previews, side chats, best-of-N comparison, and the commitment portfolio.
Browser client — /app The same client source as the desktop app, built a second time for the browser, served by the server itself. Made for a headless Linux box you reach over a tunnel, a tailnet, or a TLS hostname.
Operations console — /admin Live activity, session transcripts with search, approval gates, receipts, commitments, services, incidents, config editing, and channel onboarding.
HTTP + SSE server The contract everything above speaks: sessions, runs, approvals, transcripts, diffs and steering, with Last-Event-ID resume so a dropped connection rebuilds rather than silently losing events.
Chat gateways Telegram, Discord and Slack bridges plus outbound webhooks, with fail-closed approval forwarding.

Absent, not broken

A browser tab has no native file dialog. A chat message has no diff viewer. The rule for that is one line long.

Where a host genuinely cannot provide a capability, the capability is absent — the control is not rendered at all — rather than present and failing when pressed. A disabled button that never explains itself, or a dialog that opens onto nothing, teaches a reader to distrust every other control on the page.

So the browser client asks the server's filesystem for a directory rather than pretending to open a native picker, and the terminal is off by default over a network because a shell reached from a browser is a different security question from a shell on your own desk.

  • Capabilities are declared by the host, not guessed by the client.
  • What a host cannot do is hidden, never stubbed.
  • What it can do behaves identically to every other surface.

The contract they share

This is the part that makes "one core, many surfaces" a claim you can check rather than a diagram.

One policy engine Agent turns, tools, workers, flows, plans, evals, server runs and desktop runs all pass the same gate before dispatch.
One ledger format Append-only JSONL with branch lineage and compaction-as-entry, wherever the run started.
One receipt Purpose, model, failure domain, settlement and usage, for every provider dispatch on every surface.
One frozen execution contract Recorded at admission, so what a session was allowed to do cannot drift underneath it while it runs.
