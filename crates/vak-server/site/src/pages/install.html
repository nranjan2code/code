Install it, run it, and take it back off

macOS and Linux. No toolchain, nothing to compile, and a lifecycle that is a set of verbs rather than a folklore of manual steps — install, verify, update, uninstall, each one checkable against a manifest.

Three commands

Setup runs once. Afterwards it shows a review rather than a wizard.

  1. 1 InstallDownloads the release for your platform and places it. Re-running it is an update. curl -fsSL https://get.vak.dev/install.sh | sh
  2. 2 Set upChoose a workspace, connect a provider, verify a model, pick a permission mode, and — only if you ask — bring up services. vak setup
  3. 3 Check itReadiness, layer by layer: provider auth, model route, config warnings, sandbox, extensions. vak doctor
macOS Vak-<version>-<arch>.dmg — drag Vak.app to Applications. The build is not yet signed, so the first launch needs right-click → Open; every launch after that is normal.
Linux vak-<version>-<arch>.tar.gz, or the bootstrap script above.
Windows Not supported, and not shipped half-done: paths, service management and sandboxing are all two-platform today, and an installer over a binary with no containment backend would be a less safe product than this one claims to be.

Headless, and in Docker

The workspace client and the operations console are served by the same binary, so a headless box needs nothing else installed to be usable from a browser.

vak serve binds loopback and serves the workspace client at /app, the operations console at /admin, and this site at /.

Binding any other interface requires [server] trusted_hosts, and the server refuses to start without it. Reach a remote box over a tunnel, a tailnet, or a TLS-terminated hostname; set [server] public_url to an https origin and the session cookie becomes Secure.

vak open opens a running server's web surface in a browser, already signed in, without you handling a token at all.

  1. · ServeLoopback by default; --host needs trusted_hosts first. vak serve --port 8901
  2. · Open a surfaceSigns the browser in for you. vak open app
  3. · DockerMulti-stage, non-root, root-owned binaries, health-checked. No Node and no Python in the image — every embedded bundle is committed. docker/build.sh --up

Always-on services

Opt-in, never implicit. A macOS LaunchAgent or a Linux systemd user service, generated from the installed manifest rather than hand-written.

Bring services onto this buildvak self services-sync — regenerates the units and reloads them against the installed binary
See the driftvak self status — build vs manifest vs per-service units, in one matrix
Chat bridgesTelegram, Discord and Slack, plus outbound webhooks. An unknown chat lands as a reviewable pending request — approve, deny or edit access from the console, never a config-file hand-edit.

Verify, update, uninstall

The install is a manifest of digests, not a pile of files someone remembers copying. Every verb below can be checked against it.

vak self installPlace this build into the managed prefix and write its manifest.
vak self reinstallClear the prefix and place the build fresh — the honest repair for a half-finished install.
vak self verifyCheck every installed component against the manifest digests. A component that does not match is named, not glossed.
vak self statusThe drift matrix: what this build is, what the manifest says, and what each service unit actually points at.
vak self stateDigest every durable file the state registry declares — or check a snapshot taken before an update against what is on disk now, which is how an update proves it lost nothing.
vak self updateOpt-in pull-and-replace from a release feed. Nothing updates itself behind your back.
vak self uninstallThe exact reverse of install: binaries, symlinks and service units. Your data home is left alone.
vak self uninstall --purgeAlso deletes the data home — sessions, ledgers, memory, receipts. Confirmed before it runs, because nothing here is recoverable afterwards.

A release carries supply-chain evidence, and an update is proven not to lose data by digesting the durable state before and after rather than by assuming it.

Building from source

Only contributors need this. A stable Rust toolchain, Git, and Node for the client bundles.
