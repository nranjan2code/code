An agent you can inspect, constrain, and extend.

vak is a local-first Rust harness for running serious general-purpose agents without giving up the receipts. Every session replays from an append-only ledger, every effect passes one policy gate before it happens, and every model dispatch leaves a receipt.

Four readings, on every surface

The console above is not a viewer bolted onto an agent. It is the record the runtime keeps anyway, rendered. These are the four things it always has to say, whether the run came from a terminal, a browser, or a chat message.

The ledger is append-only

Every session is a JSONL tree on disk, written as it happens. Anything the model could see can be reconstructed from it, in order.

Branching and compaction append — they create entries rather than editing them, so history has no writable past. A record you can quietly correct is not evidence.

Permission comes before dispatch

Agent turns, tools, subagents, flows, plans, evals, server runs and desktop runs all pass through the same policy engine before anything happens. There is no second path that skips it.

Rules compose as allow, ask and deny, and deny takes precedence. Changing the policy cancels work already in flight and rejects approvals granted under the old one.

Every dispatch leaves a receipt

A receipt records what a call to a model was for, which model answered, where a failure would belong, whether the exchange settled, and what it cost.

It is written for the dispatch that failed as readily as the one that worked — typed errors, bounded retries and preserved partial output are part of the contract, not an edge case to hide.

The run knows what it was asked

Every turn is read on seven behavioural axes — what kind of work, how long it lives, what it can break, what standard of proof it owes, how clear it is, what it needs, and whether anyone is watching.

That reading only ever narrows the run: fewer tools when fewer will do, a higher approval floor for anything irreversible. A misreading can make vak more cautious; it can never grant a tool or skip a gate.

One core, many surfaces

The surface you happen to be using is a way in, not a different product. Each speaks the same session contract to the same core, so behaviour and auditability do not change when you switch.

  • CLIexec, plan, goal mode — for scripts and CI.
  • DesktopTauri 2 app: worktrees, diffs, editor, terminal.
  • BrowserThe same client at /app, against a headless box.
  • ServerHTTP + SSE for clients of your own.
  • GatewaysTelegram, Discord, Slack, outbound webhooks.

Safety that is architectural

The posture is a setting, not a promise. Pick how much the agent may do, and the containment underneath it is the same either way.

Read what is there, change nothing

The agent may read the workspace and answer about it. Writes and shell commands are denied outright — not queued for approval, denied. Use it on a repository you have not decided to trust yet.

your own rules are evaluated first, and deny still wins
Sandboxed at the operating system Seatbelt on macOS, Landlock on Linux, and an opt-in Docker backend for Bash with no network at all.
Restricted tools run across a broker boundary Built-in tool workers are disposable and MCP servers are sandboxed separately again, so a tool cannot reach the process that called it.
The workspace is a real boundary Canonical path confinement with symlink-escape protection, so “inside the project” means inside the project.
Secrets stay out of the agent’s air Never forwarded as ambient shell or MCP subprocess state, and a project .env loads only after you have trusted that workspace.
A policy change stops work already running Tightening the rules cancels in-flight effects and rejects approvals granted under the old policy, rather than letting them land.

Start in three commands

macOS and Linux. No toolchain to install, nothing to compile, and setup runs once — afterwards it shows a review rather than a wizard.

  1. 1 InstallDownload and place the release. Re-running it is an update. curl -fsSL https://get.vak.dev/install.sh | sh
  2. 2 Set upPick a workspace, connect a provider, verify a model, choose a posture. vak setup
  3. 3 WorkOr open the workspace below and type it there instead. vak exec "fix the failing test"
Workspace Run tasks, review diffs, answer approvals, steer a run. /app Operations Sessions, receipts, commitments, services, incidents. /admin

On this machine both surfaces open without a prompt. The server binds loopback by default; reaching it by a real hostname is an explicit opt-in ([server] trusted_hosts) that it refuses to start without, and from there a browser signs in once with the access token the server printed.
