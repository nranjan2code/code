## Second session (2026-10-11): what changed

Rules the maintainer added this session: no word lists and no tuned limits
anywhere (AGENTS.md, "No word lists, no tuned limits"); tools are typed and
described so nothing is guessed; tools come and go at runtime, so quality
is each tool's own schema plus checks that run over whatever tools exist,
never a prompt line or a per-tool fix; no compatibility code; keep
`target/` clean (`cargo clean` after a full run, then build only the two
binaries).

Fixed, each traced to Vak's contract from a live turn's ledger:

- Planner: the anaphora word list (`ANAPHORA_PHRASES`, `is_anaphoric`) is
  gone. A request carries the compact card of the turn it follows and
  nothing older; `recall` reaches the rest.
- Eval gate: the replay tested packets the planner no longer makes; it now
  checks that a stored packet is a cache for its exact range.
- `legacy_implicit_cards` (older plan records) and the word-based
  `predicted_presentations` in `vak intent` are deleted.
- Card tools, all 16: every argument typed and described
  (`every_card_argument_is_described`), no argument shape crashes a builder
  (`no_argument_shape_crashes_a_card_tool`; `emit_details_card` crashed on
  a missing `fields`). Details takes `{label, detail}` records and `text`;
  comparison `aspects` are `{aspect, option, value}` records; the table's
  budget text is gone; the preview card needs a file or markup; a record's
  text field sent as a list is joined.
- Repair: `MAX_REPAIR_TURNS` and the canned refusal are gone. A failing
  tool is hinted, then shown its schema, then withdrawn for the turn; the
  turn goes on (doc 15-reliability, "Staged repair").
- Drift and card repeat: `MODEL_DRIFT_EXHAUSTION_THRESHOLD` and
  `CARD_REPEAT_EXHAUSTION_THRESHOLD` are gone; each is told once and the
  next one stands as the model's answer.
- Outcome and stop guard: a call the runtime refused before it ran
  (`vak_tools::never_ran`) and a card that was not shown are not failures
  to report. Before this a mis-named tool marked the turn "Partial result"
  and a refused `plan` made the model apologise in place of its answer.
- Prompt: the file rule no longer reads as "deliver text by writing a
  file" (doc 07 diff note).

## Open design work, in order

1. **Done: one schema-driven argument reader for every tool**
   (`vak_tools::read_arguments`, doc 04-tools "Reading arguments"). The
   card-only converters and the agent's own are deleted. It does not cut a
   text into two fields or invent a missing one, so `plan` given bare
   names is still refused for its missing `form`; whether `form` should be
   optional is part of item 2. Not yet seen live.
2. **Done, not yet seen live: the plan check** (doc 86 §2.2). It is sent
   once in a turn, says it is the runtime and not the person, and counts
   cards that name no planned deliverable instead of attributing them by
   emit order. The live run after it
   (run_01a12974-daf2-7733-9ca6-b62d19109e20, 70 s, checklist and
   comparison shown, outcome Produced) made no `plan` call, so the new
   message has only its unit tests. Still open here: `plan` is the one
   output tool not named like its siblings (the model called `emit_plan`
   and `submit_plan`), and whether a deliverable's `form` should be
   optional.
   That run also showed the reader guessing: broken JSON text for a
   checklist's `items` was read line by line and shown as items. Line
   reading is removed from the reader; only the table tool reads its own
   rows from lines.
3. **Still under the no-word-lists rule, not yet changed:**
   `ToolErrorKind::classify` (sorts errors by words in their text) and the
   agent loop's `DOOM_LOOP_THRESHOLD`, `READ_REPEAT_LIMIT`,
   `WORKERS_GATE_BLOCKS`.
4. **Doc 87 stage 2, first slice done; a design decision is open.** The
   projection publishes an answer outline for each turn with a plan
   (`OutputTimeline.answers`: the plan's sections, a card under the
   deliverable its `answers` names, nothing placed by position), and the
   client lays an answer out from it: summary first, sections in plan
   order, unplaced blocks after, two small neighbours (stats, callout)
   sharing a row. Not yet seen live with a planned turn.
   The open decision, from run_01a12997-1aa0-75c0-bf0b-c39b7ea7144b: the
   model reasoned "no tool calls needed… I'll create a stats card, a
   callout card, a steps card" and then wrote Markdown. Blocks are offered
   as tool calls beside lookups, so "no tools needed" swallows them, and
   with no plan nothing checks. Options put to the maintainer: (1) the
   answer is one structured document, requested through the provider's
   constrained output so its shape does not depend on the model's
   reasoning (recommended); (2) keep block tools and draw Markdown tables,
   lists and callouts as blocks. Awaiting the choice.
   Also done here: Save to Library is one save for the whole answer
   (`POST /library/answers`, a Markdown document of its cards and reply),
   shown only when the answer delivered no file; the per-card save and
   `/library/cards` are gone. `ArtifactKind::Card` is still in the enum so
   stored records decode; nothing creates it now. The client's card
   fixture harness (`src/harness`, `harness.html`) is deleted.
   `tests/plain-words.mjs` fails on two "receipt" strings in
   `YourData.tsx`, unrelated to this work.
5. `label` and `title` are two optional headings on most blocks that a
   caller cannot tell apart (doc 87 defines both).
6. The admin transcript API does not show a call's arguments, so a refused
   call's arguments could not be read back without the ledger.
7. Doc 87 stages 2 and 3, and the screenshots at both sizes and themes,
   are not done. Stage 3 owes a stats pack and its test.

## How to run live

`cargo build -p vak -p vak-server --bins`, then the `vak-home-8901` entry
in `.claude/launch.json` (serves `~/vak-home` on 8901 with a throwaway
token read from a scratch file; write a new token file first). Open
`vak open app --print --port 8901`'s link in the built-in browser. Read a
turn back with `GET /admin/api/sessions/<id>/transcript` and `GET /runs`.
