## How we work

- Live runs: `.claude/launch.json` entry `vak-home-live` serves the dev
  build on port 8902 with the token in `/tmp/vak-live/test-gateway-token`;
  sign in with `vak open app --print --port 8902`. `/tmp/vak-live/wait.sh`
  waits for the newest run and prints its decisions. Read a turn's calls
  through `GET /admin/api/sessions/{id}/transcript` (newest page) and its
  decisions through `GET /runs/{id}/decisions`. Restart the server after a
  rebuild; it serves the binary it was built from.
- Gate: `scripts/gate.sh` (full, timed), `--changed` while working. After a
  gate, prune old test binaries and library files from `target/debug/deps`
  (keep the newest of each name) and remove `target/debug/incremental`.
- Commits: one per finished step, message says what and why, live evidence
  named; push after each batch. Docs and AGENTS.md change in the same
  commit as the behaviour they describe.

## Traps

- `cargo test` stops at the first failing binary: a failure means the rest
  of the workspace did not run; fix and rerun the full gate.
- A test that fails only beside others reads more than it made, or acts on
  the whole home (a lifecycle pass collects other tests' Documents): fix the
  test or give it its own binary for that reason, never to hide a failure.
- `#[path]` inside a nested module resolves through directories that do
  not exist; declare a shared fixture at the crate root.
- `cargo fmt` rewraps lines between edits: re-read before a scripted edit.
- The static mockup preview always renders light; use its own theme button.
- Publishing a hosted artifact page was refused by the permission
  classifier; mockups live in `docs/assets/` and open in the browser pane.
