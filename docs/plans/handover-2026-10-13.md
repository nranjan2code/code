## What happened live, and the decisions taken

On ~/vak-home (`permission_mode = FullAccess`, sandbox off, auto-approve,
all the workspace's own settings), a turn named its file `/vak-check-note.md`.
Under Full access an absolute path is the machine's. Told only "No such
file or directory", the model ran `find /`, listed `/home` and `/tmp`, and
tried to write under `/` and `/home`. Every write failed because macOS keeps
those read-only; nothing was created. A writable place would have been
written.

The maintainer decided (2026-10-13):

- Full access stays as it is: unsandboxed, no floor that asks first. Only
  the clearer error text (step 3 above) is added.
- Live checks never run on ~/vak-home again; they run in a throwaway folder.

The maintainer was advised to move ~/vak-home off Full access and
auto-approve; that setting is theirs, do not change it. Its model was also
found changed to `qwen3.5:0.8b-mlx` during the session, not by the session.
