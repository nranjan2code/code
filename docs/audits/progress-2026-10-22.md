# Optional progress and the old plan removal — 2026-10-22

Status: historical. Shared-client browser and live route acceptance before release.
Installed native WebKit qualification is not claimed.

Released and locally installed as 8.29.0 on 2026-10-23; see
[release verification](release-8.29.0-2026-10-23.md). The checks below describe
the pre-release acceptance; native visual qualification remains open.

The maintainer rejected compatibility for the removed plan and asked to bring
back only optional progress and one reminder about explicitly unfinished work.
The parser, outline projection/wire, plan-only correction tags/reply filters and
card-delivery-based `livePlan` reader are removed. Stored ledgers are not rewritten.
The separate [navigator check](turn-navigator-labels-2026-10-22.md) covers answer
headings/card titles replacing raw request previews.

`progress` replaces a whole flat list, is loop-owned and ledgered as a normal
call/result, and is always available but optional. A dropped item needs a reason.
The latest successful list reaches the existing top semicircle and right Details
panel; none is rendered in chat. The new finding, cause and typed control use
the existing Ladder for one reminder, with wording only in `vak_control::render`.
Pending/in-progress states are the only observation. Existing output stays;
a subsequent answer stands. No list means no check. No card matching, layout,
word rules, intent reader or strands participates.

Progress declares no lookup. Citation checks and derived-from links use the
existing tool retrieval declaration with the real arguments and successful
results, so progress acknowledgements and URLs in labels cannot become sources.
The final receipt-isolation change is covered by a regression test; it does not
add a model call or change the progress view.
